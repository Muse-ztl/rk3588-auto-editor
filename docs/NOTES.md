# 实现笔记

## 数据流

```
读帧（30fps）
 └─ 每 5 帧取 1 帧（6fps）
      ├─ YOLOv8n（RKNN / NPU core0）→ DFL 解码 → NMS
      ├─ BoT-SORT：Kalman + IoU/HSV 外观代价 + ORB 全局运动补偿
      ├─ 每 2 个采样帧：HSV 直方图，给跟踪器做外观特征
      ├─ 每 3 个采样帧：YOLOv8n-pose（约 2fps），算构图分
      ├─ 每 6 个采样帧：YuNet（约 1fps），先裁人再检测
      └─ 每 12 个采样帧：画质打分（约 0.5fps）
```

所有模型都是可选的：切分模型缺失时退回 HSV 直方图，人脸/姿态缺失时直接跳过，主流程仍然能出片。

## 两遍处理

- **pass1**：只分析，不写视频。逐帧记录每个 track 的显著性、清晰度、检测分数，按 1 秒一个桶累计。
- **pass2**：整段分析完才确定主角，然后回填每个桶的"主角占比"，再选段、切割、拼接。

边分析边猜主角会抖：前几秒出现的人可能只是路人。等整段看完再选，代价只是多存一点统计量。

## 选段

桶分（默认权重）：

```
0.46 × 人物显著性 + 0.38 × 画质 + 0.16 × 正脸
```

- 人物显著性 = `0.35 × 中心度 + 0.65 × sqrt(min(1, 人体面积占比 / 0.4))`
- 画质 = 清晰度、色彩、对比度、曝光、构图五项加权
- 正脸 = 该秒内最大的五点几何正脸分
- 三项权重强制归一化；`--aes-weight` 会被夹到 `[0, 0.84]`，避免出现负权重

分数做 3 桶平滑，然后在**每个镜头内部**滑窗。窗口长度 `clamp(总时长 × 0.45, 3, 8)` 秒，窗口不跨硬切点。候选按分数从高到低贪心选，要求不重叠、总长不超过目标的 1.15 倍；一个都选不出来时才允许跨切点。

这样做的原因是：之前用阈值分组，全片分数都高时会并成一大段，再被 `max_clip` 从 0s 砍断，最精彩的部分反而丢了。

## 主角

```
0.30 × min(1, 出现帧数/60)
+ 0.24 × 平均显著性
+ 0.16 × 平均清晰度
+ 0.12 × 正脸项
+ 0.10 × 平均构图分
+ 0.08 × 平均检测置信度
```

正脸项 = `min(1, 命中次数/10) × (0.6 + 0.4 × 平均正脸程度)`。正脸证据按"秒"记账，不按 track id：硬切或人物转身都会让 ID 重建，按 ID 记账会漏掉同一个人。

## 模型

| 用途 | 模型 | 位置 | 输入 |
|---|---|---|---|
| 检测 | YOLOv8n（9 输出 DFL 版） | RKNN / NPU | 640×640 letterbox，FP16 或 INT8 |
| 跟踪 | BoT-SORT（自实现） | CPU | 检测框 + HSV |
| 切分 | TransNetV2 | ORT / CPU | 100×27×48×3 uint8，8fps |
| 姿态 | YOLOv8n-pose | ORT / CPU | 640×640，17 关键点 |
| 人脸 | YuNet 2023mar | ORT / CPU | 640×640，先裁人再检测 |

检测输出是 3 个尺度 × (box 64 / cls 80 / sum 1) 共 9 个张量，RKNN 返回的 layout 可能是 NCHW 也可能是 NHWC，代码里按维度判断，两种都支持。

模型转换时把 `/255` 放进 RKNN 的 `std_values=255`，C++ 只做 letterbox + RGB。这样校准集读原图、
线上推理也读原图，INT8 的输入分布才是同一个。

检测器的 I/O 有两条路径：默认零拷贝（输入 FP16 + `pass_through`，输出 `rknn_set_io_mem`），
失败时回退到 `rknn_inputs_set`/`rknn_outputs_get`。`--no-zero-copy` 可以强制走旧路径做 A/B。

## 测量

- `--bench N`：只跑检测，前 3 次预热，输出 p50 / p95 / 各阶段 p50，以及 RSS、CPU 占用、温度、NPU/CPU 频率。
- `--bench-json PATH` 把结果落盘；`--dump-dets PATH` 导出最后一帧检测框，用来做逐位对比。
- 完整跑：`--analysis-fps 6 --core-mask 1`，记录 pass1、pass2、各阶段调用次数。
- 分位数是最近秩，取排序后 `floor(p/100 × (n-1))`，和历史 report 口径一致。
- 同一段素材重复跑，检测 p50 会在 65～95ms 之间波动，和板子频率、温度、后台负载有关；
  README 和 `docs/OPTIMIZATION.md` 里取的是同一轮完整跑/bench 的数据，原始值在 `assets/`。

## 没做 / 做得很糙

- INT8 已经能跑（person recall 97.9%），但框抖动会让实拍素材的选段从 5–12s 偏到 4–11s，
  所以默认仍用 FP16。要上线得先让跟踪器/选段对量化抖动更稳，或者做 QAT。
- 外观特征是 HSV 直方图，不是 OSNet；换 ReID 模型只需要替换 `hsv_features`。
- 姿态是 YOLOv8n-pose，不是 RTMPose。
- 只支持单机位、无音频；成片音轨被丢掉。
- 权重（0.46/0.38/0.16、显著性 0.35/0.65）是在少量素材上手调的，没有做大规模参数搜索。
